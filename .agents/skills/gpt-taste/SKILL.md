# Cinematic editorial preset

Use this preset when explicitly selected or when the brief clearly calls for cinematic editorial web design. Choose its techniques from the content and existing brand; it is not a general requirement for every frontend task.

Choose a hero and component structure deliberately. If random variation is explicitly requested, use an actual random operation and describe only what ran. Never simulate Python execution or present a mocked tool transcript as evidence.

## Visual vocabulary

- Hero options: a wide centered statement, artistic asymmetry, or an editorial split. Let heading width and scale support readable wrapping on the actual viewport and locale, rather than guarantee a fixed line count from CSS alone.
- A marketing page may use Attention, Interest, Desire, and Action as a narrative aid. Do not add sections, pricing, CTAs, or testimonials absent from the product or request.
- Use broad section rhythm for cinematic content, tighter grouping within components, and clear primary actions. Whitespace is intentional when it serves hierarchy.
- A bento can vary card sizes while preserving logical reading and focus order. Check actual grid placement; `grid-auto-flow: dense` can reorder content and is not mandatory.
- Inline imagery, an accordion gallery, a typography band, or a testimonial module are options when relevant. Use genuine sources for people, quotes, and customer logos.

## Motion

Use existing CSS or motion tooling for the selected interaction. Check installed GSAP, ScrollTrigger, and framework adapters before importing them. Pinning, scale/fade, text reveal, and card stacking are optional techniques; do not require them in every page.

Clean up animation instances and observers. Preserve ordinary scrolling, keyboard access, and usable content with reduced motion or JavaScript unavailable. Avoid infinite marquees without an appropriate pause mechanism. Do not hide overflow globally to conceal an animation layout defect.

## Working boundaries

The user's brief, existing brand, real content, platform conventions, and repository instructions take precedence over aesthetic examples. Preserve functioning routes, data flows, translations, semantic HTML, keyboard access, visible focus, and responsive behavior within scope.

Use supplied or verified assets and facts. Do not fabricate execution, metrics, prices, dates, contact details, certifications, endorsements, customer logos, or testimonials. Clearly label fictional sample content when a mockup calls for it; never change real values to make a layout look more natural. Check installed dependencies and font availability/licensing before introducing them.

Motion is optional. Respect reduced-motion preferences, keep content usable without animation, provide keyboard/touch equivalents for hover behavior, and avoid decorative loops that obscure status. Check contrast on the actual background; WCAG AA normal text needs 4.5:1, while large text (18pt/24 CSS px, or 14pt/about 18.67 CSS px bold) needs 3:1. Preserve stricter project requirements.
