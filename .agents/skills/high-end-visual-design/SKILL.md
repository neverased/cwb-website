# Refined visual preset

Use this style when selected by the brief. Premium character comes from coherent decisions and execution, not assumed budgets, compulsory animation, or a ban on common fonts.

## Optional directions

- **Ethereal glass:** dark neutrals, translucent surfaces, precise highlights, and a restrained accent.
- **Editorial luxury:** warm paper or deep espresso, expressive headings, careful image placement, and generous measure.
- **Soft structuralism:** light neutrals, strong hierarchy, airy grouping, and subtle ambient depth.

Select available, licensed fonts that fit the brand. Geist, a distinctive grotesk, or an editorial serif may work; preserve the existing stack when appropriate. Use the installed icon family consistently rather than force a new dependency.

## Components and layout

Asymmetric bento, layered cards, and editorial split layouts are optional. Keep mobile reading order clear and remove overlaps that obstruct content or touch targets. A normal grid is valid when it serves the content.

A nested shell with a small inset, an inner highlight, and concentric corner radii can suggest material depth. Use it selectively; plain cards, borders, conventional buttons, and ordinary navigation are valid. A trailing icon enclosure should not create nested interactive controls.

Use whitespace proportional to the content and viewport. Prefer fluid widths and appropriate dynamic viewport units for full-height areas. Do not force every section to a minimum cinematic height.

## Motion and performance

Purposeful press, hover, menu, or entry transitions can support feedback. Immediate state changes and static content are valid, especially for reduced-motion users. Avoid hiding all content behind a reveal.

Favor transform and opacity for frequent motion, limit large blur/filter areas, profile effects that stutter, and clean up observers. Keep overlays from intercepting unintended input. Use the project's layer scale instead of arbitrary z-index values.

## Working boundaries

The user's brief, existing brand, real content, platform conventions, and repository instructions take precedence over aesthetic examples. Preserve functioning routes, data flows, translations, semantic HTML, keyboard access, visible focus, and responsive behavior within scope.

Use supplied or verified assets and facts. Do not fabricate execution, metrics, prices, dates, contact details, certifications, endorsements, customer logos, or testimonials. Clearly label fictional sample content when a mockup calls for it; never change real values to make a layout look more natural. Check installed dependencies and font availability/licensing before introducing them.

Motion is optional. Respect reduced-motion preferences, keep content usable without animation, provide keyboard/touch equivalents for hover behavior, and avoid decorative loops that obscure status. Check contrast on the actual background; WCAG AA normal text needs 4.5:1, while large text (18pt/24 CSS px, or 14pt/about 18.67 CSS px bold) needs 3:1. Preserve stricter project requirements.

## Completion

Complete the requested artifact or change, then check the affected surface at representative sizes and relevant interaction states. Run focused project checks appropriate to the change. Repeat checks after meaningful fixes or new evidence, not for an arbitrary pass count. Report only checks actually performed and any remaining limitations; do not claim a rendered or generated result without evidence.
