# Generation and review

## Prompt

Describe the target surface, user task, supplied references, exact authorized copy, chosen composition, palette, typography character, media, and requested output size/count. Prioritize legible content over tiny ornamental labels. A static image can suggest intended states, but it does not prove implemented motion or working controls.

Use the image tool's reference inputs when editing or retaining a supplied visual. Do not claim to have generated or inspected an image without actual tool output. If the requested tool is unavailable, explain the concrete limitation and provide only a useful fallback the user can use.

## Multiple views

Generate multiple sections or alternative directions when requested, or when a specific missing detail prevents the intended handoff. Establish a shared palette, typography, navigation, radii, and media treatment before expanding the set. A larger image or inspection zoom may resolve readability without new generation.

A deliverable might be one hero concept, a whole-page overview, a focused section, or a requested design pack. These are alternatives, not a mandatory ladder of escalating outputs. Preserve approved choices when correcting later views.

## Review and completion

Inspect actual generated images for spelling, legible copy, alignment, visual hierarchy, asset consistency, and adherence to the brief. Check that factual claims are supported and mock content is labeled. Fix concrete defects, then stop when the requested concept is usable. Do not chase endless stylistic alternatives.

Return the actual generated images or artifact paths through the tool's supported mechanism. Identify unresolved limitations such as small text or missing source assets. If implementation was not requested, the completion boundary is the reviewed image deliverable; do not claim that a functioning website was built.
