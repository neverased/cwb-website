# Visual craft guidance

Use this reference for a substantial visual design decision, not as a required reading list for every UI edit. The brief, existing brand, product facts, platform, and accessibility requirements govern the work.

Typography should establish a readable hierarchy and comfortable measure. A body measure around 65–75ch is a useful starting point for prose; compact controls and tables differ. Choose display scale and tracking using real copy and actual viewports. Do not impose a universal heading size ceiling or forbid a brand's font.

Use color roles consistently. Check text against the actual surface: normal text needs 4.5:1 contrast, while large text (18pt/24 CSS px, or 14pt/about 18.67 CSS px bold) needs 3:1. Preserve stronger project requirements. Check placeholder and muted text too. Do not choose a theme or replace approved colors from category stereotypes.

Use grouping, spacing, rules, or cards according to information and interaction. Consistent components can be valuable; nesting is a problem when it obscures hierarchy or wastes space, not by definition. Keep a coherent layer scale and prevent popovers from being clipped by ancestors.

Motion is optional and should explain state, relationships, or a requested experience. Keep content visible by default, respect reduced motion, support keyboard/touch interaction, and profile expensive effects when warranted. Static content and instant state changes are valid. Do not add custom scrollbars, decorative loops, or complex animation solely to demonstrate craft.

Write concrete copy with meaningful control labels. Preserve the user's approved voice and exact factual content. Familiar fonts, gradients, warm neutrals, borders, card radii, or section labels are design choices to evaluate in context, not automatic failures.

Inspect the affected rendered surface and relevant states, fix observed defects, and run appropriate existing checks. Stop cosmetic iteration once the brief is satisfied and material findings are resolved. Further checks need a change, failure, or unresolved concern; never report unperformed tests or generated assets as complete.
