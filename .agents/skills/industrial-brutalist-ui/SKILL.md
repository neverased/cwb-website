# Industrial and brutalist UI

Use this as a selected visual direction, not a default for dashboards or any data-heavy product. Combine Swiss typographic structure with mechanical labeling only where it supports the brief and audience.

## Visual vocabulary

- Rigid modular grids, clear dividing rules, and strong alignment.
- Large display type contrasted with compact functional labels; preserve readable body text and controls.
- Neutral surfaces with restrained utilitarian signal colors, consistent with the real brand and status semantics.
- Monospaced or tabular numbers for aligned data, with units and timestamps drawn from real sources.
- Optional halftone, scanline, or print-wear texture that stays behind content and does not obscure text or focus.
- Sharp geometry, utilitarian buttons, technical diagrams, and schematic framing where they help understanding.

Treat telemetry as product data. Do not invent live statuses, signal strengths, coordinates, serial numbers, certifications, or trademark symbols as factual decoration. If a requested concept uses simulated telemetry, label it clearly as sample data and keep the same values consistent across views.

Animations, glitch effects, and blinking terminal treatments are optional. Keep them brief or pausable where required, respect reduced motion, and never use animation to imply real activity or operational health. Maintain conventional affordances for forms, navigation, and destructive controls.

## Working boundaries

The user's brief, existing brand, real content, platform conventions, and repository instructions take precedence over aesthetic examples. Preserve functioning routes, data flows, translations, semantic HTML, keyboard access, visible focus, and responsive behavior within scope.

Use supplied or verified assets and facts. Do not fabricate execution, metrics, prices, dates, contact details, certifications, endorsements, customer logos, or testimonials. Clearly label fictional sample content when a mockup calls for it; never change real values to make a layout look more natural. Check installed dependencies and font availability/licensing before introducing them.

Motion is optional. Respect reduced-motion preferences, keep content usable without animation, provide keyboard/touch equivalents for hover behavior, and avoid decorative loops that obscure status. Check contrast on the actual background; WCAG AA normal text needs 4.5:1, while large text (18pt/24 CSS px, or 14pt/about 18.67 CSS px bold) needs 3:1. Preserve stricter project requirements.

## Completion

Complete the requested artifact or change, then check the affected surface at representative sizes and relevant interaction states. Run focused project checks appropriate to the change. Repeat checks after meaningful fixes or new evidence, not for an arbitrary pass count. Report only checks actually performed and any remaining limitations; do not claim a rendered or generated result without evidence.
