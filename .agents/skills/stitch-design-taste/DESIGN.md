# Example design specification

This is an illustrative template for a restrained editorial interface, not the identity of any real project. Replace sample choices with the requested project's supplied brand and verified tokens. Do not copy this file into a project unchanged.

## Purpose and atmosphere

A readable, calm surface with clear hierarchy and enough whitespace to distinguish groups. Set density and visual expression from the real audience and task.

## Color roles

- Canvas: use the project's primary background token.
- Surface: a related neutral for meaningful grouping.
- Text: a foreground checked against each background.
- Accent: the approved action or selection color.
- Status: semantic success, warning, and error roles with non-color cues.

Record actual color values and foreground/background pairings when known. Normal text needs 4.5:1 contrast; 3:1 large-text contrast applies at 18pt/24 CSS px or 14pt/about 18.67 CSS px bold. Do not label unmeasured pairings as compliant.

## Typography and layout

Use available, licensed brand fonts and a readable type hierarchy. Keep prose at a comfortable measure and allow translated strings to wrap. Choose grids, rows, cards, or dividers according to content. Adapt layout to available space without hiding essential content or forcing every screen into one column.

## Components and interaction

Define labels, primary and secondary actions, focus, selected/disabled states, and applicable loading, empty, and error behavior. Preserve semantic controls and keyboard/touch access. Use real destinations and factual content; label any illustrative data.

## Motion and constraints

Motion is optional. If selected, describe the interaction it supports, reduced-motion behavior, pause controls where needed, and performance constraints. Essential content is visible by default. List actual project restrictions, not universal bans on fonts, colors, card counts, or layouts.
